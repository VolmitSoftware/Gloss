# Editor demonstrations

`fixtures/` contains editable Gloss documents. `shots.json` specifies actual authoring controls, preview interactions and exported values for each recording. The fixture import establishes the initial document; the recorded sequence edits it through the editor.

Run these commands from `Gloss/gloss-web/`. Build the production editor with `dart run jaspr_cli:jaspr build`, then serve `build/jaspr` on a loopback port. Run `node test/demo/capture.cjs <shot-id> ...` with the `playwright` Node module and `ffmpeg` on PATH. `PLAYWRIGHT_MODULE` and `FFMPEG` override those defaults. `GLOSS_WEB_URL` names the served editor (required). Raw frames, screenshots, clips and metrics stay under ignored `.qa/demo/captures/`.

Capture uses native 1920×1080 Chromium frames and their compositor timestamps. Clips contain continuous cursor movement, typing and preview actions, are silent 30fps WebM, and must remain below 25MB. Each take checks its exported document and browser errors; ffmpeg decodes the entire output. `node test/demo/verify.cjs <shot-id> ...` additionally checks real Chromium video playback, advancing decoded frames and middle/end seeking.

These clips demonstrate browser authoring and local previews. Local form fields use a browser dialog; commands and external actions appear in the action log. They do not execute server commands or prove native Minecraft rendering. Player heads use the bundled preview skin, and entity types without a shipped rig use approximate catalog sprites. Server-connected sessions require a real editor connection.

For a server-connected take, run `/gloss editor pair` on the owned test server and set `GLOSS_PAIR_LINK` to the link it prints (good once, for 10 minutes; keep it out of tracked files) with `GLOSS_FAKE_SERVER` unset; with `GLOSS_FAKE_SERVER` the script pairs with that fake Gloss server instead. `node test/demo/live-sync.cjs` pairs through the pairing card, opens `GLOSS_DEMO_DOCUMENT` (default `showcase`), records the first-page text and visibility edits, and writes `.qa/demo/live-sync-ready` once staged. With a live server it waits for `.qa/demo/live-sync-publish` before clicking Publish; start the actual native recording after staging and before creating that coordination file. With the fake server it publishes at once. The script requires the server's Applied acknowledgement before accepting the browser take; the native recording proves the resulting world display separately.
